# تقرير التنفيذ والجاهزية — خليجي تايم

**3 نوفمبر 2026 — نسخة محلية على فرع جلسة مستقل، ليست إصداراً منشوراً.** النطاق `alshafra.com` وجميع مسارات خريطة الموقع باقية. لا دمج في `main` لأن ذلك قد يطلق الإنتاج، ولم يتغير DNS أو حسابات الإعلانات أو قاعدة الإنتاج، ولم يُطلب فحص AdSense. اجتياز الاختبارات الآلية أدناه لا يعني اكتمال المراجعة التحريرية أو القانونية أو قبول AdSense أو ترتيباً محدداً.

## المنجز

- الهوية الظاهرة وmetadata وmanifest والتوليد الثابت و404 و410 والإدارة تحمل «خليجي تايم». صورة المشاركة الحالية رسم محايد دون شعار لفظي، ولم تُعد تصميمها. اسم فريق تحرير تقويم السعودية أبقي كما حدده صاحب الموقع: هو تعريف الفريق، لا تسمية العلامة التجارية الجديدة، ولم تُدّعَ له مؤهلات جديدة.
- حاسبة العمر `/age-calculator` هي الوجهة الأساسية لنية العمر: مدخل ميلادي أو هجري، التحويل والمقارنة بين شخصين (تاريخ الثاني ميلادي)، النتيجة تُحدّث تلقائياً وزر «عرض نتيجة العمر» ينقل تركيز لوحة المفاتيح إليها، مثال نهاية شهر وتنبيه عن الرؤية والبلد والجهة. التحويل يعتمد على `Intl` بالمتصفح وليس اتصالاً مباشراً بموقع أم القرى؛ يرفض الحساب عند غياب الدعم اللازم، ولا يثبت الاختبار دقة كل تاريخ أو جهاز. لم تُنشأ صفحة ثانية للنية نفسها.
- مسارات `/age-calculator` و`/date-converter` و`/countdown` معزولة مسبقاً، وأضيف `/about` و`/contact` و`/privacy` و`/terms` و`/faq` و`/articles`: لا سكربتات أو خطوط طرف ثالث في HTML الخاص بها، CSP مقيّدة، وإخفاء مواضع الإعلانات والروابط الإعلانية، وتنقل بمستند مستقل لدخول العزل والخروج منه. على الصفحات الأخرى توجد مواضع/سكربتات إعلانية قائمة؛ لم تُختبر الشبكات الحية، ولم يُحسم امتثالها. لا تغيير لحساب الإعلان أو إعداداته الحية.
- أُزيل تكرار WebSite من الرئيسية ومخطط Breadcrumb ذي العنصر الوحيد، وأزيل WebApplication غير المناسب من HTML الثابت لمركزي الرواتب والمدارس. FAQ إن بقي متوافقاً مع المحتوى لا يضمن ظهور نتيجة غنية؛ [Google أوقف ميزة FAQ](https://developers.google.com/search/docs/appearance/structured-data/faqpage) منذ مايو 2026. يبقى تدقيق كل schema المرئي على الإنتاج مهمة مستقلة.
- رابط جدول المالية السنوي الذي أعاد 404 في فحص 3 نوفمبر استُبدل برابط وزارة المالية الرئيسي، **وليس** دليلاً على جدول صرف؛ المواعيد لا تعتمد على قاعدة 27 وحدها أو الرابط العام. لا يظهر موعد مدرسي غير معتمد، ولا تصرفات غير معتمدة في بوابات التطوير. لم يُعتمد أي موعد حكومي جديد ولم تُنشأ صفحات بلدان أو مواعيد غير موثقة.
- [جرد 47 صفحة](جرد-الصفحات-خليجي-تايم-2026-11-03.md) يتضمن القالب والغرض والمصدر والإعلانات وcanonical وschema والقرار الأولي؛ و[صورتا الحاسبة](screenshots/) التُقطتا محلياً بعرض جوال وسطح مكتب، مع حجب الأطراف الثالثة وبيانات افتراضية، وليستا صوراً للإنتاج.

## البنية، الأساس والتغييرات غير المنفذة

React/TypeScript وVite مع بناء HTML ثابت لـ47 مساراً؛ لا SSR عند كل طلب. `scripts/prerender.mjs` يولد HTML وsitemap، وVercel الاستضافة الحالية. إعدادات Netlify الموجودة ليست دليلاً على سلوك Vercel. قبل التكليف الحالي نجح `test:all` بـ66 اختباراً. نتيجة فحص HTML السابق 47/47 وجود عنوان ووصف وcanonical وH1؛ لا يثبت الفهرسة أو الزيارات. ملاحظة صاحب الموقع أن الصفحات مفهرسة وأن تقارير Search Console فارغة؛ لم تتوفر بيانات تحقق مستقلة.

المقالات المنشورة في نسخة الموقع مصدرها ملفات المشروع وتبنى من جديد؛ قاعدة Supabase التطويرية وإدارة المحتوى ليست متصلة بنشرها. مشروع `alshafra-dev` سبق اختباره ببيانات اصطناعية وRLS وtransactions متراجعة؛ لا migration في هذه الدفعة ولا تعديل بيانات إنتاج. حساب مستخدم الإدارة واختبار Auth/PostgREST حقيقي والتزامن وربط النشر الآمن ما زالت غير مكتملة؛ الاختبارات الحالية mock/local، فلا يجوز تصوير اللوحة كجاهزة للإنتاج.

## الاختبارات والقيود

- بعد التغييرات: `npm run test:all` نجح **67/67** (31 تواريخ وثقة، 12 SEO وتوجيه، 19 إدارة، 5 UI)، ويشمل TypeScript وESLint والبناء. `npm run test:browser` نجح **6/6** منفرداً بعد البناء على Chromium المحلي، مع اختبارات الإدخال والأطراف الثالثة وتبديل المسارات وتركيز نتيجة العمر بـEnter وaxe على ست صفحات أولوية. اختبارات أمثلة 29 فبراير ونهايات الأشهر والتحويل وفروق الأشخاص لا تثبت صحة كل نطاق `Intl`. اختبارات axe آلية جزئية، لا تغني عن قارئ شاشة وفحص يدوي شامل.
- HTTP وتوليد 404/410 والتحويل واختبارات الروابط داخلية محلية؛ لا تثبت استجابة Vercel الفعلية. اختبارات الخصوصية لم تر إرسال تواريخ اصطناعية في الشبكة أو URL أو التخزين داخل سيناريوهات Chromium، مع حجب الأطراف الثالثة؛ لا تغطي إضافات المتصفح أو أي إصدار منشور آخر. لا تُرسل تاريخ الميلاد عبر analytics أو API أو URL، ولا تضعه في localStorage؛ التحقق التشغيلي على المعاينة الفعلية مطلوب بعد النشر المصرح فقط.

## العمل المتبقي قبل قرار الإطلاق

1. مراجعة بشرية فردية لكل مقال وعدّاد وصفحة زخرفة: الأصالة، الفائدة، المصدر الرسمي، الفئة والدولة، تاريخ التحقق وتاريخ انتهاء المراجعة والمحرر المعتمد؛ إعادة التحقق من المواعيد فور تغير الجهات، وعدم عرض تقدير حسابي كإعلان حكومي. تحقق خاص لمصدر جدول المالية البديل، لا تستنتجه من رابط الوزارة العام.
2. اختبار لوحة الإدارة الفعلي على التطوير بحساب مصرح وصلاحيات واقعية وسباق عمليات ومراجعة أمان وخطة نشر وإبطال جلسات وربط محتوى قابل للتراجع؛ دون دخول قاعدة إنتاج أو بيانات إنتاج غير مصرح بها. عدم تأجيل اللوحة يعني أنها من متطلبات القرار، لا أنها جاهزة الآن.
3. مراجعة القوالب الإعلانية كافة على معاينة آمنة بأجهزة مختلفة، بما فيها إعلانات الشبكات عند تصريح منفصل؛ تحقق من عدم حجب عناصر التحكم أو تضليل الزائر أو زيادة الإعلانات على المحتوى. راجع الإفصاحات والخصوصية والشروط قانونياً. [سياسات Google](https://support.google.com/adsense/answer/10502938?hl=en) لا تضمن القبول.
4. فحص مستخدمين فعليين ولوحة مفاتيح وقارئ شاشة وتباين وجوالات ومتصفحات، والتأكد من تطبيق CSP وHTTP والـcanonical وOG وschema و404 وسitemap على Vercel معاينة فعلية. لا تعمم اختبارات المحلي على Vercel.
5. إعداد قياس بعد الإذن والامتثال للموافقة: Search Console على النطاق المناسب، أداء الظهور والنقرات والاستعلامات والصفحات وحالة الزحف؛ GA4 إن استُخدم بأحداث عامة مثل فتح الأداة أو استخدام زر بلا تواريخ ميلاد أو قيم حقول أو معرفات شخصية في event parameters/URL، مع فحص DebugView/Network وسياسة الموافقة. لا مقاييس قبل جمعها ولا اختلاق خط أساس. صفحات الأدوات المعزولة حالياً لا تحمل سكربت تحليلات، فلا تفترض تتبعها.
6. جدول متابعة مقترح 30/60/90 يوماً بعد إطلاق مصرح: أولاً التحقق من أخطاء HTTP/الفهرسة والمصادر وتجربة التحكم، ثم قراءة الاستعلامات وصفحات الهبوط والتفاعل المسموح، ثم مراجعة تحسينات المحتوى حسب البيانات. لا أهداف عددية أو وعد ترتيب قبل توافر خط أساس كافٍ. لا تغييرات 301 أو حذف أو noindex دون فحص روابط ومقصد وفهرسة وبيانات متاحة وخطة استرداد.

## الاسترداد والقرار

لا تدمج `main` ولا تدفع إنتاجاً في هذه المرحلة. التراجع المحلي يكون باستعادة الملفات المطلوبة من النسخة إلى مجلد منفصل، ومراجعة diff والاختبارات قبل تطبيقها؛ لا تستبدل المستودع أو قاعدة البيانات عشوائياً. في حال نشر مستقبلي مصرح وحصول خلل، تُختبر إعادة توجيه النشر إلى إصدار Vercel سابق سليم ضمن إجراء الإصدار وموافقة صاحب الموقع؛ تحقَّق من النطاق والـHTTP والبيانات بعد التراجع. لا تتضمن النسخة قاعدة بيانات، ولا تنفذ rollback قاعدة أو DNS دون خطة ونسخة خاصة وموافقة. يلزم إغلاق المتطلبات أعلاه والمراجعة ثم تفويض مستقل قبل أي فعل يطلق الإنتاج.
